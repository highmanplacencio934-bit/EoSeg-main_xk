# 同seed baseline差异：GPU验证后的解决方案

更新：2026-10-27 America/Denver。本轮完成用户指定服务器定位；未修改生产代码或训练参数。20分钟时的旧方案作为历史证据归档到审计目录solution_plan_before_gpu_validation.md。

## 1. 已确定的问题

同seed不能控制当前CUDA损失归约与反向计算的全部浮点执行顺序。现在已有完整受控证据链，而非只根据PyTorch警告推测：

1. 同一best177分别经旧/ROI入口完整12例96Dice逐值相同，均84.7184661015%，且与原在线CSV一致。
2. 初始化388状态、原生CPU/CUDA RNG、真实Batch顺序/增强、最终随机点/匹配均一致。
3. 同输入、同网络输出下，损失归约出现约2.38e-7的微差，反向梯度不同；同一旧入口重复也发生。
4. 第1步LR全0但AdamW内部状态已分叉；第2步非主干LR按原规则升到4e-7，23个可训练参数张量分叉。
5. 原3D CE和grid_sample反向固定输入重复试验分别复现非确定性，strict deterministic分别明确拒绝。

因此ROI评分入口、受控初始化/数据/采样不同不是本次受控分叉的原因。当前实现存在真实可复现的CUDA数值非确定性，这能解释为什么seed0仍不保证训练结果一样。不能精确反推历史84.7185%与85.9138%之差1.1953pp分别来自哪一算子或多少其他未记录因素。

## 2. 方案选择与baseline影响

| 方案 | 用途 | 是否改变baseline | 当前状态 |
|---|---|---|---|
| 保留原训练协议与全部历史成绩 | 忠于作者现有baseline | 不改模型/训练/数值协议；接受不可逐位复现事实 | 当前默认，生产未改 |
| 独立运行清单与首批/采样/RNG/AMP/实际step记录 | 让后续分叉可追踪 | 不改公式；同步记录可能改变执行时序，不能承诺非确定训练结果零影响 | 本轮审计已实现，不自动全量接入 |
| 独立确定性对照入口 | 研究并减少同seed波动 | 模型/LR可保持，但数值实现与运行协议改变，不能冒充原baseline同轨迹 | 仅建议，需后续授权 |
| 多次匹配预算/seed重复并报告全部结果 | 衡量训练方差与创新稳定性 | 不替代原baseline；新增实验预算 | 本轮未启动 |

保持作者baseline时，不能为了让两次Dice一致而改seed、减少随机增强、固定所有裁剪、减少采样点或挑选更接近论文的权重。也不能把ROI加速的速度收益写成精度提升。

## 3. 如果需要确定性对照，按以下顺序单独实施

### 3.1 先处理分类CE的非确定归约

当前实际实现对B×Q×C logits转置为B×C×Q后调用weighted CrossEntropyLoss，走nll_loss2d CUDA路径。独立候选是将logits/targets展开为(BQ)×C和(BQ)，保持原类别权重、背景/no-object、reduction语义与梯度目标。孤立试验中该2D候选稳定且strict通过。

它的浮点归约顺序与旧路径不同，实际loss会有ULP级差异，因此不是逐位等价补丁；要单独命名、保留原入口。验收需覆盖类别权重/no-object、不同有效器官数、输入dtype/AMP、随机标签与梯度对照，并记录新旧数值误差。

**只修CE不足以保证训练确定性。** 本轮孤立CE虽前向有微差，梯度在该试验中稳定；全损失的梯度还受grid_sample反向影响。

### 3.2 再处理point_sample的反向

保持原num_points12544、oversample3、importance.75、坐标选择、双线性插值、align_corners=False及边界规则，设计或选择确定性的等价数值实现。不能直接改nearest、改坐标、改采样数量或移除不确定点选择。

验收至少包括同输入同坐标30次前向/反向hash一致、CPU双精度参考/梯度检查、坐标边界与越界情况、真实criterion输入重放、FP16/compile兼容、峰值显存与时长。若最终依赖CPU回退或自定义kernel，应明确数值路径、性能和兼容性差异。该实现尚未开发，不提前承诺可无损替换。

### 3.3 严格验证完整短轨迹

仅在隔离入口开启strict deterministic（非warn_only），保留原模型、数据、优化器和所有科学参数。如其他算子报错，逐项处理，不将警告忽略后称为确定性。

用本轮相同脚本逐级验证：初始化→同Batch一次真实更新→原生多个Batch→跨独立进程重复；检查输入、RNG、采样、loss、AMP跳步、AdamW moments和参数。严格区分第1步LR0的optimizer调用与后续真实非零LR参数变化。关闭compile或改FP32可用于单独诊断，不能默认为最终修复，且不能保证消除原CUDA归约/反向非确定性。

### 3.4 再决定是否做完整重复训练

短轨迹一致不证明220轮、跨GPU/驱动/版本一定逐位一致。完整重复必须另行授权，匹配220轮/171–220选择窗口和1-view/固定8-view口径，并报告全部结果。新增确定性协议和历史原baseline分开记录，不覆盖旧成绩。
