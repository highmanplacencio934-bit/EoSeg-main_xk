## HD95实际公式与独立验证

当前training/lightning_module.py:1010的非空分支调用MedPy0.5.2的binary.dc与binary.hd95；后者先提取3D表面，再求每个表面点到另一表面的最近欧氏距离。采用connectivity=1、默认单位spacing。实际实现为：

```text
Dice(P,G) = 2|P∩G| / (|P|+|G|)
D(P→G) = { min_{g∈surface(G)} ||p-g||₂ : p∈surface(P) }
HD95 = percentile95(concat(D(P→G), D(G→P)))
```

不是最大Hausdorff，不是两个方向95分位数再取最大，不是表面平均距离，也不是把95%乘到距离上。不同实现可能定义不同；此处只确认当前实际路径符合MedPy本身。

使用SciPy KDTree直接从表面点坐标计算最近邻，在20组固定seed的随机3D二值掩码上，与实际baseline函数HD95最大差值0，Dice与体素计数公式最大差值0；另做可手算的位移掩码核对。因此本次未发现非空掩码的Dice/HD95公式实现错误。安装环境中的hd95/表面距离源码另存文本，作为当前版本证据。

默认没有传voxelspacing，返回体素网格距离，不是毫米。固定掩码沿axis0相距3个体素时，默认HD95=3，显式spacing=(2,1,1)时变为6，说明spacing确实会改变距离。当前H5没有可用真实spacing元数据，不能事后把75.17标成mm，也不能为了减小值擅自补任意spacing。

来源：[MedPy作者文档与源码](https://loli.github.io/medpy/_modules/medpy/metric/binary.html#hd95)。本地实际版本0.5.2，文档页面标0.4.0；本次以安装源码和独立计算为当前版本证据，未假定文档版本与环境相同。

## 发现的独立空GT计分错误（本轮未修正）

当前实际函数在pred非空、GT为空时返回Dice=1、HD95=0。对这种非空/空情况，Dice分子为0而分母为正，按Dice公式应为0，记为1确实会奖励纯误检。双方都空时当前返回0，属于另一个需明确约定的边界规则，不能与上述确定的错误混为一谈。

全12例真实GT存在性核对发现：epoch177的case0035/class2胆囊GT为空，CSV Dice=1、HD95=0，触发了该满分分支。左右肾与肝脏12例GT均非空，因此这个错误不解释三项高于论文的分数，也不解释本轮肝脏高HD95。它会影响胆囊及整体均值：若仅将该非空/空Dice改0、其余结果保持不动，胆囊均值会少100/12=8.3333个百分点，整体8类均值少1.0417个百分点；这是诊断性反事实计算，不是新baseline成绩。

本地project_TransUNet/TransUNet/utils.py及[TransUNet官方utils.py](https://github.com/Beckschen/TransUNet/blob/main/utils.py)有相同返回分支，说明不是本次汇总时新增的错误。仍不能因来自参考实现就把纯误检满分解释为正确Dice。修正会改变当前评估口径，按用户保持baseline的要求，本轮只报告，没有修改代码、CSV或训练状态。
