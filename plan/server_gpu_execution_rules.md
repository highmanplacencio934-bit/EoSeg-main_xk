# 服务器GPU并发与显存规则

更新：2026-10-26，America/Denver。用户明确授权，适用于本EoSeg Synapse项目已获授权的服务器训练、测试和冒烟。

1. 服务器上有其他用户执行任务也可以运行。现场剩余显存足以覆盖本次配置的预计峰值及必要临时开销，即可直接执行，不要求GPU空闲，不需要再次申请并发例外。
2. 启动前用nvidia-smi核验GPU、实际进程与剩余显存；以同配置实测峰值优先估算本次需求。训练需计入梯度和优化器状态，推理需计入相应batch/TTA，以及compile和工作区开销。模型文件大小或模型已加载的占用不能替代峰值估计。其他进程存在或GPU利用率较高，不单独构成拒绝执行的理由。
3. 剩余显存不足则不启动，记录预计需求与实际余量，等待资源释放或向用户报告。不得中止、暂停、重启或向其他用户进程发送控制信号，不得GPU reset或清理他人任务来腾显存。运行中若显存变化导致本次任务OOM，只处理本次任务并保留证据，不能停止其他用户任务。
4. 不因显存不足静默减batch、改输入/精度/梯度累积或其他科学变量。当前运行任务的权重、源码、配置、数据和结果保护继续适用。任务本身仍须有用户授权，不能因允许资源并发自行新增实验。
5. 本项目既定消融队列的顺序、共享锁、幂等回执和PID归属核验继续防止重复启动；它们不要求服务器没有其他用户GPU进程。不得把其他用户的进程当作本项目任务操作。
6. 本规则优先于旧文档的“GPU必须空闲”“有其他任务就deferred”“并发需每次另行授权”等资源限制。历史记录中GPU空闲、其他用户占用、等待或单次许可等事实保持原样，不能倒改。
7. 本次只更新规则文档。部分历史启动器仍可能有gpu_free/GPU busy或固定阈值硬检查；它们是现有代码限制，不能被误称为当前用户禁止并发。不得为此擅改正在运行任务的冻结代码或绕过验收/防重复锁；后续实际执行时使用满足本规则和原参数的独立入口，或在隔离修改并验证后适配启动器。

执行环境仍为服务器项目`/Disk/HDD/Sk/EoSeg-main_Synapse_acdc/EoSeg-main_synapse`，不是本地PowerShell进程。Python命令保留HF_HUB_OFFLINE=1、TORCH_HOME=/Disk/HDD/Sk/.cache/torch、TIMM_USE_OLD_CACHE=1，解释器和其他环境核验按AGENTS.md及terminal_conventions.md执行。
